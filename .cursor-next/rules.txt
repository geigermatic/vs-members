When writing code:
1. Project Initialization Order:
   a. Define core domain model first
      - Entity relationships
      - Business rules
      - Value objects
      - Aggregates
   Note: See /templates/supabase-viewer.md for example domain model
   b. Identify reusable components
   c. Choose between local packages or npm registry
   d. Set up actual database schema
      - Start with minimal viable schema
      - Plan for extensions
      - Document constraints
   e. Create API layer
      - Real endpoints from day one
      - No mock data
   f. Build UI components based on real data

2. Project Structure (Domain-Driven):
   /src
     /domain              # Core domain models and logic
       /entities         # Business entities
       /valueObjects    # Immutable value objects
       /aggregates      # Aggregate roots
     /infrastructure    # External services, DB
       /api            # Real API implementations
       /database       # Database access
     /application      # Application services
       /services      # Use cases
       /dto          # Data transfer objects
     /presentation    # UI layer
       /pages        # Route components
       /components   # UI components
       /state       # UI state management
